# SD 竹筒：UX 框架 v0.2

## 最新决定：社区主页与五个底部入口

以下决定取代 v0.1 的角色入口与页面导航；原有共同池分配规则继续保留。

所有普通用户使用同一个 app 和账号，可以同时捐款、申请帮助、发帖、点赞与分享文化；管理员使用独立工作台。公开主页不标注捐助者或受助者身份。

底部导航固定为：**主页 / 地图 / 财务 / 消息 / 我的**。

- **主页**：类似 Twitter 的社区动态。点击名字查看作者主页，点赞可取消，所有人可以发帖。顶部持续显示自己的 streak 与今天的参与状态。
- **地图**：暂定展示社区活动、服务站、帮助领取点。这是待确认的用途假设；草图只用虚构位置，不代表实际地点或私人住址。
- **财务**：捐款入口、自己的捐款记录、共同池到账和支出。资金仍统一入池，不向帖子作者直接打赏。
- **消息**：可从作者主页开始聊天，也可咨询社区团队。本版是本地聊天请求预览，不发送给真人；正式版需要请求接受、屏蔽和举报机制。消息是可后置的 MVP 功能。
- **我的**：公开帖子、编辑名称和介绍、私下申请帮助、善意墙展示选择、设置。设置含互动通知和陌生人聊天请求。

### 文化交换

社区发帖入口提供“家里的食谱”“家乡故事”等引导。收到帮助后，私人页面再次邀请用户分享自己的文化或生活经验，可以跳过。贡献包括钱、故事、食谱和人与人的交流；公开分享不成为获得帮助的条件。

### Streak 暂定口径

沿用捐款 streak，不把发帖或点赞当作捐款。顶部同时显示“今天已分享”，承认不同贡献。是否把它进一步改成多种善行共同累计的 streak，留待讨论，不自动改变原规则。

### 本轮内部检查

按 design-everyday-things 的五项诊断，暂评 8/10：入口、结果反馈、操作与结果对应、基本输入约束已覆盖；完整错误恢复未覆盖（资料取消与聊天草稿仍需完善）。这是设计自查，不是用户可用性测试结果。

---

以下保留 v0.1 的资金与帮助流程，供追溯。

一句话：每个人放一点钱，汇入城市共同竹筒；管理员核实需要、安排帮助，大家看见城市正在发生的善意。

## 先看懂三个角色

| 角色 | 心里想的事情 | 主流程 |
| --- | --- | --- |
| Alex，想捐钱 | 我只有一点钱，也能参与吗？ | 选金额 → 确认进入共同池 → 支付成功 → 小树成长 → 自愿上墙 |
| Maria，需要帮助 | 我能得到帮助，又不必公开自己的困难吗？ | 私下申请 → 等待核实 → 查看安排 → 收到帮助 → 自愿同意匿名近况 |
| 管理员 | 哪些需要已核实？还能安排多少钱？ | 核实申请 → 批准并预留 → 记录拨付和送达 → 检查公开授权 → 更新近况 |

一个人可以同时是捐助者和受助者。原型顶部的角色切换是评审工具；正式产品的管理端需要独立权限。

## 页面怎么分

- **我的竹筒**：金额、单次确认、支付结果、成长记录。
- **城市近况**：已核实的帮助进展。捐款统一进入共同池，帖子不设置个人收款。
- **城市善意墙**：所有头像一样大，不显示金额、不排名。公开参与者并不等于某个案例的直接资助者。
- **共同账本**：到账、费用、已预留、已拨付、可安排余额。
- **申请帮助 / 我的申请**：私人资料、核实进展、领取安排、公开偏好。正式版从公共首页提供入口。
- **管理员工作台**：私人申请、核实、分配、执行凭据、公开授权。

## 一个具体例子

Alex 已连续参与 14 天，今天放入 $0.10。模拟支付成功，共同池从 $200 变成 $200.10，小树成长，收到第 15 天上墙邀请。他可以拒绝，也可以主动选择公开头像。

Maria 私下申请食物支持。管理员核实后从共同池预留 $50；帮助送达后才记为已拨付。若 Maria 同意发布指定的匿名文字，城市近况才出现“一个家庭已收到 $50 食品支持”。

Maria 看见整面善意墙，知道社区有人愿意支持她。系统不声称 Alex 的那一笔钱直接给了 Maria。

## 核心规则与待定草案

**已确定的理念**：金额不影响成长速度；钱进入共同池；没有催捐；公开身份自愿；头像等大；申请帮助不以捐款或公开故事为条件。

**本版假设**：连续 15 天收到邀请，门槛可调整。建议漏一天只中断连续天数，不让植物死亡、不收回已获得的纪念。这个规则仍待你决定。

**支付边界**：目前全部为模拟。真正的小额支付、结算和费用规则尚未设计完成；不能把未付款的心意记录计为已到账捐款。每日多次捐款也只算一天。

**隐私边界**：捐助者展示头像和受助者公开故事，是两份独立的授权。默认均不公开，撤回后停止展示。公共账本不展示私人联系方式。

## 这一轮先验证什么

请让初次接触的人完成三个任务：

1. 放一点钱后，说明钱去了哪里，是否指定给某个人。
2. 拒绝上墙，并说明自己的贡献是否仍然有效。
3. 申请帮助但拒绝公开故事，并找到申请进展。

记录是否独立完成、卡在哪一步，以及对共同池的误解。当前没有做真人可用性测试，也不把内部检查当作测试结果。
